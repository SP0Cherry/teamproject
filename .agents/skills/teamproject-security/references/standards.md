# 安全开发规范

以下规范覆盖浏览器、服务端、后台任务、文件存储、向量索引和外部 AI 服务。授权以服务端当前身份和资源关系为准，前端隐藏入口、文件标识难以猜测或模型自行判断均不能替代安全校验。相关清单、配置与测试随功能实现维护。个人数据始终按账号隔离，组共享和通知发布均校验当前成员权限。

| 规范项 | 本项目的开发要求 | 检查与验收方式 |
| :--- | :--- | :--- |
| SEC-01 默认拒绝（default deny） | 新接口和后台管理能力默认不可访问，必须按“路由+方法”显式登记认证要求、角色及资源策略。注册、登录等公开接口逐项登记，不用通配符放行整个业务模块；未匹配策略、未知角色及权限服务异常均拒绝访问。后台任务使用独立服务身份，仅获得所需权限。 | 新增未登记接口、切换 HTTP 方法、模拟权限服务失败，均不得获得业务数据或产生写入；检查公开清单无扩大范围的通配规则。 |
| SEC-02 逐资源授权判定 | 单条资源先取行再校验归属或成员关系（fetch-then-check），也可使用同时约束资源标识与授权范围的查询；校验完成前不得返回正文、计数、预览或触发副作用。个人待办、通知、文件、切片、会话、日报、消息及异步任务均独立校验；嵌套路径同时校验父子关系。跨用户或跨小组的无权资源统一按不存在处理。列表先限制授权范围，再筛选、分页与计数；批量操作逐项校验，不能只校验第一项。 | 替换资源标识、父小组标识，混入一条他人记录并重放批量请求；应返回约定错误，且不得发生部分越权写入或泄露总数。 |
| SEC-03 附件与文件读取 | 禁止仅凭文件标识或存储路径读取内容；原文件、缩略图、OCR 文本及引用预览必须绑定已授权的业务文件对象，逐次校验当前权限。文件不放公开静态目录，对象存储默认私有；首期由鉴权服务代理预览与下载，不暴露可绕过撤权校验的长期直链。服务端生成存储标识，不接受用户传入本地路径；下载文件名与响应头须安全编码。删除文件、退出小组后原访问入口立即失效。 | 换账号读取同一文件、匿名打开地址、构造路径穿越、退出后复用下载地址，均不得获取文件内容；缩略图和引用预览执行同样测试。 |
| SEC-04 越权失败场景 | 每条资源读写场景配对水平越权用例，每条角色受限功能配对功能级越权用例。至少覆盖个人文件与待办互访、访问他人会话与任务状态、越权编辑资料。另测组外访问、普通成员越权管理、越权撤回他人通知和退出后读取历史引用。只有当前成员可以修改自己的组同步设置，组管理员也无权代改。异步任务执行时复核当前授权和资源有效性。同步写入待办时同时复核同步设置。 | 场景清单与用例清单逐项对应；缺少越权用例视为未覆盖。验证替换用户或组标识不能修改无权设置。任务入队后退组或关闭同步，执行时不得写入待办。 |
| SEC-05 认证与会话 | 密码使用带独立随机盐的专用单向密码哈希算法，如 Argon2id 或 bcrypt，并集中管理强度参数；禁止明文、可逆加密或普通摘要存储。认证错误不暴露账号是否存在；密码重置凭证短期、单次有效，不能用于登录业务接口。令牌、密码及重置凭证不进入 URL 查询串和日志。会话有到期时间，并通过服务端会话记录或账号版本支持退出、管理员撤销和改密后立即失效，不能仅等待令牌自然过期。 | 检查密码字段与日志；测试错误账号提示、重置凭证复用、退出后旧令牌和改密后所有旧会话；旧凭证应被拒绝。 |
| SEC-06 令牌存放与轮换 | 访问令牌仅放内存，不写入 localStorage、sessionStorage、IndexedDB 或前端持久化缓存。刷新令牌放 HttpOnly、Secure、SameSite=Strict Cookie，限定必要路径，服务端仅保存其安全摘要；每次刷新轮换，旧令牌重放时撤销对应会话令牌族。前端并发刷新须协调，避免误用已轮换令牌。生产环境全程 HTTPS；开发例外必须显式配置且不能带入生产。 | 检查浏览器持久化存储及 Cookie 属性；重放旧刷新令牌、并发刷新及改密后刷新，核对轮换与撤销行为，页面脚本不得读取刷新令牌。 |
| SEC-07 CSRF 与跨域 | 跨域来源使用精确白名单，携带凭证时禁止通配来源；SameSite Cookie 之外，使用 Cookie 的刷新、退出等写操作还须校验 Origin，并按部署方式使用 CSRF 令牌。GET 不修改业务状态；不得因缺少 Origin 就无条件接受 Cookie 写请求，非浏览器调用须使用明确的独立认证方式。 | 从未授权域发送预检、携带 Cookie 的写请求及伪造刷新请求，应被拒绝；合法前端刷新和退出仍可完成。 |
| SEC-08 密钥与机密 | 密钥仅由环境变量注入，不打包到前端、镜像构建参数或仓库文件；首次提交前建立忽略规则，样例只含键名和空值/占位值。数据库、对象存储和模型凭证按环境隔离并最小授权。任何真实密钥进入提交历史、日志或镜像层均视为泄露：立即吊销并轮换，排查访问记录，再处理历史残留；删除当前文件不能代替轮换。README 记录轮换步骤和验证方法。 | 扫描工作区、全部提交历史、构建产物与镜像层；演练替换凭证，确认旧凭证失效且服务可恢复，不在演练输出中打印机密。 |
| SEC-09 外部内容不可信 | 上传正文、OCR 结果、检索片段、模型输出及外部工具描述均作为不可信数据。资料放在明确标记的用户/工具数据区，不拼入系统指令；系统提示声明不执行资料内的指令。提示词约束只是一层防护：检索范围、工具白名单、参数校验及权限判定必须由服务端执行，模型不得决定授权。首期 AI 不获得任意文件读取、网络请求、执行命令或直接修改正式待办的能力。 | 上传要求忽略规则、泄露其他小组资料、读取密钥或调用未授权工具的内容；即使模型生成相关请求，服务端仍应阻断，且正式待办不被直接修改。 |
| SEC-10 出站地址白名单 | 模型、OCR、存储等出站目标由部署配置及适配层白名单决定，不接受用户参数或文件中的链接直接作为服务端请求目标；首期不提供任意 URL 拉取与回调能力。后续开放时须校验协议、域名、端口及解析后的地址，阻断环回、私网、链路本地、云元数据等非授权目标；重定向逐跳复核，并防止 DNS 重绑定。文档解析器禁止自动加载外链、远程模板和嵌入资源。 | 提交内网地址、编码变体、重定向和含外部资源的文档，确认请求被拒绝；结合模拟目标访问记录验证没有实际出站，不能只看应用日志。 |
| SEC-11 输入校验与批量赋值 | 按白名单校验类型、长度、范围、枚举与字段集合，拒绝未声明字段。客户端传入的用户标识、小组标识、文件标识均不可信；归属由服务端身份及资源关系确定。输入对象与持久化对象分离，不允许直接绑定 `owner_id`、角色、审批/确认状态、存储路径等受控字段；确认待办及轻编辑资料只接受对应操作允许编辑的业务字段，编辑资料不能更改归属或共享范围。 | 传入错误类型、超范围值及额外的所有者、管理员角色、目标状态字段，应被明确拒绝，数据库受控字段不得变化。 |
| SEC-12 输出转义与注入防护 | 按 HTML、属性、URL 等输出上下文编码；AI Markdown 与文件预览禁用原始 HTML 或使用受控净化器，链接协议走白名单，不执行上传脚本、宏或嵌入对象。查询一律参数绑定；动态列名来自固定映射。调用解析工具使用参数数组，不将文件名或用户文本拼接到 shell 命令。配置适合部署的 CSP，不能用其替代转义与净化。 | 在标题、文件名、正文和 AI 回答中加入脚本、事件属性、危险链接、引号与命令字符，均不得执行；参数化查询及工具调用应保持数据语义。 |
| SEC-13 文件解析隔离 | 文件处理遵循产品大小与内容限制，同时防御 DOCX 解压炸弹、超大图片、恶意 PDF、路径穿越和解析器异常。解析进程采用低权限、受限网络及独立临时目录，限制 CPU、内存、解压后体积、文件数量和执行时长，禁止宏与主动内容执行；临时文件在成功、失败和超时后清理。失败不能落入无限重试或阻塞其他用户任务。 | 使用受控异常样本测试超时、解压超限、异常图片和目录穿越；处理应受限终止，不能访问宿主敏感目录或拖垮正常任务。 |
| SEC-14 敏感数据与 AI 数据边界 | 集中定义密码、令牌、邮箱等字段的响应可见范围和脱敏规则；认证机密永不进入响应，必要账号资料只向有权用户返回。日志、追踪、错误报告默认不包含文件正文、完整问题、模型提示或回答。调用外部 AI 仅发送当前任务必要且有权使用的片段，不发送凭证或无关用户数据；在上传或问答入口说明外部处理范围。不得未经说明将用户资料用于训练或共享测试。 | 抽查响应、日志、追踪及模拟模型出站请求；不得出现机密、无关资料或跨组内容，脱敏实现应复用统一规则。 |
| SEC-15 滥用防护与资源配额 | 注册、登录、重置、上传、AI 问答和任务重试设置按账号及来源的速率限制；文件存储、解析并发、文本长度和模型用量设配额，具体值集中配置并记录。身份相关接口的限制不得只依赖可伪造的客户端标识。超限返回 429 及可重试信息，不泄露账号存在性；同一失败任务不能通过无限重试消耗资源。 | 连续调用、并发上传、大量提问与反复重试，检查限流、配额和队列隔离；单个用户超限不应耗尽其他用户可用资源。 |
| SEC-16 依赖引入与许可证 | 新依赖登记用途、来源、版本和许可证，直接与传递依赖均纳入检查；初始自动许可白名单为 MIT、BSD-2-Clause、BSD-3-Clause、Apache-2.0、ISC，其他许可或未知许可须在引入前完成兼容性评估并留记录。版本锁定文件入库；容器基础镜像使用可追溯版本或摘要，不使用漂移的 latest。构建记录依赖清单，禁止从未登记来源临时下载并执行脚本。 | 核对清单、锁文件、构建来源及许可证；未登记依赖、未知许可或白名单外且无评估记录的依赖不得合入。 |
| SEC-17 依赖漏洞扫描 | 新增/升级依赖、每次合并请求和发布构建触发漏洞与机密扫描，已发布依赖每日巡检。严重及高危漏洞阻断合并和发布；中危登记负责人并在 30 天内修复，低危在 90 天内处理。线上严重/高危发现后 24 小时内完成影响核查和隔离，严重漏洞 72 小时内、高危 7 天内修复或移除依赖；无补丁时关闭受影响能力并跟踪。误报须有证据、责任人及到期日，不能永久全局忽略。 | 引入受控的高危依赖验证构建失败；检查扫描任务是否按时触发，风险记录是否有负责人、期限及处置证据，过期例外不得继续放行。 |
| SEC-18 删除、撤权与安全审计 | 文件删除先在业务层使访问立即失效，再异步清理原文件、切片、向量与缓存。小组撤权立即收回对应账号的访问权并失效其派生缓存，其他有权成员仍可使用共享文件与索引。清理失败时可重试，访问失效须持续生效。审计记录认证异常、权限拒绝、成员角色变更、通知发布/撤回和机密轮换等事件，记录身份、对象、时间、动作和请求标识，不记录机密正文；安全日志限制访问与修改。生产上线前在 DATA-07 指定的留存清单定义业务数据、审计及备份保留期和删除恢复策略，并由 README 链接，禁止从备份恢复后绕过已生效的删除或撤权记录。 | 清理任务失败时重试读取与检索，仍应拒绝；模拟备份恢复后复核删除和权限标记；检查关键事件可追溯，普通成员不能读取或覆盖安全审计。 |
