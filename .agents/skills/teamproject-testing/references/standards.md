# 测试规范

测试以产品场景和已声明契约为依据，优先验证业务结果、权限边界及失败恢复，避免仅复述实现或断言返回形状。验证未加入任何小组的用户仍可完成个人主流程。首期同时覆盖小组创建、加入、资料共享与成员按组选择通知同步。

| 规范项 | 本项目的测试要求 | 检查与验收方式 |
| :--- | :--- | :--- |
| TEST-01 测试层次 | 单元测试覆盖时间计算、状态流转、权限规则等业务逻辑；接口测试覆盖每条能力的正常与失败路径，事务、唯一约束和并发使用真实测试数据库验证；端到端优先覆盖注册登录、上传通知并确认待办、资料阅览编辑与问答、查看日报等主路径。小组主路径覆盖创建、加入、共享及发布后按成员设置同步。 | 统计各层用例，检查业务边界是否下沉到单元或接口层，避免用端到端重复覆盖所有分支。 |
| TEST-02 用例来源 | 每个产品场景至少对应一组用例，以场景编号或文档链接双向关联；权限、幂等、撤权和故障恢复等规范中的失败场景也须有对应来源。资料编辑覆盖新版本可检索和旧版本失效，并模拟重建中及重建失败；日报覆盖 AI 不可用时基础清单仍可见。通知同步用例覆盖同组不同成员及同一成员在不同组的设置隔离、默认关闭、开启前的通知、关闭后保留已有待办、队列延迟时关闭再开启、退组和重复投递。 | 对照场景清单与用例文件，检查遗漏及无来源、无实际业务判据的用例。 |
| TEST-03 三类组织 | 用例按正常路径、失败路径、边界归组，目录或名称明确分类；失败路径逐项覆盖规约，不以数量代替覆盖。边界测试覆盖合法区间两端及相邻非法值，如文件上限、分页上限、截止时刻和日期切换。 | 核对三类用例及失败场景映射，缺类或漏项即未完成。 |
| TEST-04 数据隔离 | 使用独立测试数据库或 schema，以及独立文件目录、索引和队列命名空间；用例自行建立并清理数据，失败时也执行清理。禁止连接生产数据，不依赖执行顺序或上条用例残留；并发用例使用独立连接。 | 随机排序、重复及并行执行，结果应一致；清理范围必须限制在本次测试命名空间。 |
| TEST-05 外部依赖 | 模型、OCR、对象存储、消息等外部服务和业务时钟使用可注入替身，不访问真实外部服务、不等待真实截止时间；替身须能模拟超时、无效输出、重复消息与依赖失败。测试数据库等本地依赖由测试环境统一准备。 | 准备本地依赖后断开外网运行，全部测试仍应通过；推进测试时钟即可验证临期、逾期及提醒。 |
| TEST-06 一键运行 | README 写明一条完整测试命令、环境变量、本地依赖准备方式、退出码和报告位置；该命令覆盖规定的单元、接口及主路径端到端测试，不要求手工调用真实 AI 或调整业务数据。 | 新成员按 README 完成准备后执行一次命令，可复现结果和报告。 |
| TEST-07 通过判定 | 任一失败均以非零退出码阻断，不保留“已知失败”作为通过依据。跳过用例登记原因、负责人、恢复期限及替代验证方式，不得用跳过掩盖回归；已交付能力的关键用例不得跳过，已有跳过项不得无理由增加。 | 检查失败时构建退出码、跳过清单及到期项；存在未解决的必测失败或关键用例跳过即未通过。 |
| TEST-08 断言有效性 | 判据是“改坏被测规则，用例是否失败”。断言具体业务码、任务字段、持久化结果、副作用次数、授权范围及引用来源，不能只断言不报错、长度一致或字段存在。关键规则可通过临时移除权限条件、去重或时间边界进行轻量变异验证，验证后恢复改动。 | 对关键逻辑引入一次会改变行为的缺陷，相关用例必须变红；仅做等价改写不作为有效验证。 |
| TEST-09 缺陷判定的信号口径 | 本项目有独立业务码，以 `code` 判断业务接受或拒绝，同时独立校验后端规范规定的 HTTP 状态；HTTP 200 且业务码拒绝不能视为业务成功，但属于 HTTP 契约不符。异步 202 仅表示受理，须继续检查任务终态与实际结果；下载和流式回答按其专用契约判定，流中错误不得视为正常完成。 | 检查 HTTP 200+拒绝业务码、202+后台失败、流式中途错误三类响应，分别识别业务结果、协议问题和处理终态。 |
| TEST-10 缺陷的四个判定词 | “被当成成功”：失败操作被响应或界面宣告成功；“被放行”：未授权或不满足规则的操作获得数据或产生副作用；“被误拒”：满足契约和权限的合法操作被拒绝；“未处理故障”：异常导致挂起、无明确终态、泄露堆栈或仅返回“系统错误”等无下一步提示。预期失败被正确拒绝属于用例通过。 | 抽查失败报告，按这四类描述实际行为与预期；不同评审者应得出一致结论。 |
| TEST-11 响应时间阈值 | 固定本地或 CI 环境、数据规模和预热条件，记录正向接口请求从发出到收到完整响应的耗时；初始普通接口超过 300ms 标记、超过 1000ms 不通过，异步任务提交超过 1000ms 标记、超过 2000ms 不通过。上传传输、解析/索引完成及 AI 生成按文件规模与能力单独登记两档阈值，不套用普通接口标准；未登记不得声称性能验收通过。负向用例不计入上述正向耗时统计，但仍须有超时保护。 | 在固定性能测试任务中输出逐条耗时；两档之间仅标记，超过第二档阻断。业务时钟可冻结，耗时测量使用真实单调计时。 |
| TEST-12 变更要求 | 业务行为变更补充或更新对应场景用例；缺陷修复先补能复现问题的回归用例，再修复。纯文案、排版等低影响变更使用适当走查，不机械新增重复测试；变更说明记录验证结果与适用范围。 | 对照改动、场景及验证记录，确认行为变化有有效覆盖，修复用例在修复前失败、修复后通过。 |
