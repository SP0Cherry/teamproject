# 部署与运维规范

以下规范适用于接口服务、后台解析与索引任务、提醒调度及其依赖；部署参数、处置步骤与演练记录随实现维护。小组资料共享与按成员设置同步属于首期部署验收范围。

| 规范项 | 本项目的部署与运维要求 | 检查与验收方式 |
| :--- | :--- | :--- |
| OPS-01 可复现构建 | 依赖锁定文件入库；Dockerfile 分阶段构建，最终镜像仅包含运行所需产物，不含开发依赖、测试数据或机密。固定基础镜像摘要与构建工具版本，控制构建时间戳等非确定因素；镜像使用版本号或提交号标签并记录摘要，不覆盖已发布标签。 | 同一提交在相同构建参数下构建两次，比对产物内容与摘要；差异须定位，不能仅凭标签相同认定一致。 |
| OPS-02 环境与配置 | 开发、测试、生产三级环境使用同一镜像，仅替换运行时配置；数据库、文件存储、向量索引、队列与凭证按环境隔离。密钥与普通环境配置分开管理，通过环境变量注入；前端环境变体使用运行时配置，不把机密打包到浏览器。 | 同一镜像切换环境无需重建；测试环境不得访问生产数据，必填配置缺失应启动失败。 |
| OPS-03 健康检查 | 存活与就绪端点分开：存活判断进程能否工作，就绪检查接流量必需的依赖；不就绪时停止接流量。模型等可选能力故障单独报告并明确降级，避免因外部服务短暂故障反复重启。停止时先取消就绪、停止接收请求及领取任务，再等待在途工作；后台长任务超出退出期限须可重新领取并幂等恢复。 | 模拟关键依赖未就绪与模型故障，检查流量及降级行为；停止服务时在途请求在退出期限内正常完成，长任务可恢复且不重复生成待办。 |
| OPS-04 结构化日志 | 单行 JSON，统一字段 request_id、timestamp、level、module；后台任务另带 task_id，异步链路保留原始请求关联。记录状态、耗时及脱敏错误，不记录密码、令牌、文件正文或完整模型提示。 | 抽样一次上传或通知发布，能关联接口、Outbox、解析或同步任务日志，且不存在敏感原文。 |
| OPS-05 指标与告警 | 至少监控请求量、错误率、时延、依赖连通情况；补充解析/索引失败率、队列积压时长、提醒延迟及模型用量。每条告警登记统计窗口、阈值、责任人、恢复条件和处置动作，避免瞬时故障反复通知；上线前完成配置。 | 制造依赖失败、任务积压或提醒延迟，核对告警能触发、指向责任人并给出处置入口，恢复后可消除。 |
| OPS-06 发布与回滚 | 单实例部署可按记录的维护窗口更新并验证恢复。需不中断服务时采用滚动或蓝绿发布，接口与后台任务版本须兼容发布期间的数据及事件；提供一条命令回滚至上一镜像版本或摘要。README 记录发布、验证、回滚和必要补偿步骤，发布前演练。应用回滚不自动回滚数据库或撤销已发布通知，相关数据和副作用按兼容及补偿方案处理。 | 发布后检查登录、通知确认、任务查询、资料检索和日报。验证组资料共享和组通知发布，并用同步设置不同的成员核对待办结果。执行回滚并记录耗时，旧版可正常处理未完成任务。 |
| OPS-07 数据变更顺序 | 结构变更先于代码发布且向后兼容，按需要执行加字段→双写及回填→切读→停止旧写→删旧字段；删除操作放在回滚窗口结束后。迁移独立执行并防止并发重复运行。切片或向量模型升级使用版本化索引，重建验证后切换，保留旧索引用于回滚。 | 旧版代码在新结构上仍可运行；检查回填完整性、迁移重复执行保护及索引切换后的查询与权限隔离。 |
| OPS-08 备份与恢复 | 上线前写明数据库与原文件的备份频率、保留期、加密和访问权限，以及恢复点目标 RPO、恢复时间目标 RTO；目标须与实际备份能力匹配。向量索引可重建，但须保留重建所需原文、切片版本及配置，并计入恢复时间。至少每季度恢复演练，重大存储变更后追加演练；恢复后重新应用删除与撤权记录。 | 在隔离环境恢复，记录耗时与数据缺口，核对 RPO/RTO、原文件完整性及已删除/撤权内容不可访问；只有备份成功记录不算通过。 |
| OPS-09 性能与容量 | 固定负载与数据规模并登记预算，首期列表接口 p95 不超过 500ms，单次超过 300ms 记录为慢操作；线上预算与既有单条测试阈值分别验收。上传、AI 首段响应及解析/索引总耗时按文件规模另设预算。批量大小、解析并发、队列容量和外部调用配额集中配置，遵循既有文件上限；耗时可定位到数据库、检索或模型调用。 | 定期采样时延分布及慢操作；使用代表性个人资料、长通知和并发量验证容量，补充代表性小组规模与通知投递容量场景。超预算时能定位具体调用，不能以异步受理耗时代替任务完成耗时。 |
| OPS-10 限流与配额 | 写接口、上传、模型调用和检索按账号或小组等授权主体限流，并设置全局并发与成本上限；多实例共享限流状态。超额请求在执行或入队前拒绝，返回明确错误与重试建议，不能无限排队。已受理任务按有限重试与配额策略执行，避免故障重试放大费用。 | 连续及跨实例发起超额请求，应得到 429 与重试信息；被拒请求不得入队、生成重复任务或产生模型调用费用。 |
| OPS-11 发布留痕 | 每次发布在 docs/releases/ 归档版本号、提交号、镜像摘要、变更内容、配置/迁移及索引版本、验证结论、发布时间与执行人，关联回滚或恢复演练记录，不记录机密配置值。失败发布和实际回滚同样留痕。 | 按版本标签可找到记录，并对应实际运行镜像与数据版本；发布、失败及回滚时间线完整可查。 |
