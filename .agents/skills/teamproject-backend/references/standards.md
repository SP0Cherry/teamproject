# 后端开发规范

以下规范适用于 HTTP 接口、后台任务及外部能力集成，不预设具体语言或框架。接口契约、错误码、配置项及异步任务清单须随实现维护在项目文档中。

| 规范项 | 本项目的开发要求 | 检查与验收方式 |
| :--- | :--- | :--- |
| BE-01 分层与依赖方向 | 接口层→业务层→数据访问抽象，由数据访问层实现数据库读写；OCR、文档解析、模型、向量库、对象存储和消息服务通过外侧适配层接入。业务层定义所需接口，不依赖厂商 SDK、HTTP 请求对象或具体存储实现。禁止接口层直接操作数据库、业务层直接编写查询语句、适配层反向调用接口层。后台任务通过业务层执行流程，不复制业务规则。 | 按目录与导入关系检查新增模块；业务层出现 SQL、ORM 查询或厂商 SDK 调用，接口层绕过业务层查询数据库，均判违规。 |
| BE-02 接口命名与版本控制 | 资源使用小写复数及 `/api/v1` 前缀，如 `/tasks`、`/files`、`/groups/{group_id}/members`。GET 读取，POST 创建，PUT 完整替换，PATCH 局部修改，DELETE 删除；路径不用动词。流程动作通过资源表达，例如 POST `/notifications/{id}/publications` 发布、POST `/tasks/{id}/completions` 完成；具体流转仍由业务层校验。破坏性契约变更引入新版本并声明旧版本停用计划。 | 路由清单与接口文档逐项核对；检查路径、方法语义以及 GET 是否产生业务写入，使用静态检查约束命名。 |
| BE-03 请求与响应结构 | 普通 JSON 接口统一返回 `{code, message, data, request_id}`；失败时 `data` 可包含字段错误等结构化明细，不返回堆栈、SQL 或供应商原始错误。所有响应携带请求标识，HTTP 状态须表达真实结果，不把所有失败包成 200。异步提交成功返回 202 和任务标识、状态查询地址，不宣称处理完成。文件下载及流式 AI 回答在契约中声明专用格式，其错误与结束事件也须可识别并关联请求标识。 | 对照接口文档检查成功、校验失败、异常和异步返回；新增普通接口复用统一封装，流式失败不得被误判为完整答案。 |
| BE-04 错误码体系 | 维护唯一错误码清单：参数 `PARAM_*`→400；认证 `AUTH_*`→401；授权 `ACCESS_*`→403；不存在 `RESOURCE_NOT_FOUND`→404；版本或流程冲突 `CONFLICT_*`→409；请求过大→413；格式不支持→415；业务规则不满足 `BUSINESS_*`→422；限流→429；依赖不可用/超时 `DEPENDENCY_*`→503/504；未预期内部异常→500。对无权查看且需隐藏存在性的对象统一返回 404，并在文档中声明。每个错误码登记含义、HTTP 状态和恢复建议，客户端不通过匹配中文消息判断错误。 | 比对清单与实际返回值；清单外错误码、同码多义、状态码不符或暴露内部异常均判缺陷。 |
| BE-05 参数校验的位置 | 接口边界完成必填、类型、长度、枚举、格式及文件限制校验，只将已校验的输入对象交给业务层。业务层负责成员资格、资源归属、时间先后、状态流转等业务不变量，并在需要时于事务内复核；后台任务也必须经过相同业务规则。不得把“接口已校验”当作跳过业务一致性检查的理由。 | 发送缺失字段、错误类型、超长文本和非法枚举，均返回统一错误；绕过 HTTP 调用业务流程时仍不能突破权限或状态规则。 |
| BE-06 数据访问与事务 | SQL、ORM 查询及持久化操作只出现在数据访问层，事务边界由业务层按一次业务操作定义，关联仓储共享同一事务上下文。通知确认与候选任务整批入库须原子提交。流程更新使用当前状态和版本号条件更新，并检查受影响行数。数据库结构变更通过版本化迁移执行；破坏性迁移先备份并提供恢复方案，不声称不可逆操作可直接回滚。 | 审查仓储调用、条件更新和迁移脚本；在中途注入失败验证整批回滚；在测试库验证可逆迁移回滚或不可逆迁移的备份恢复流程。 |
| BE-07 事务内的禁止项 | 事务内仅保留必要的数据库读写及一致性校验，禁止外部 HTTP、模型推理、OCR、向量生成、文件上传和直接消息投递。通知发布等操作由业务层在同一事务写业务记录及 Outbox 事件；投递器提交后发送，消费者幂等处理并记录结果。文档须说明投递者、消费者、超时、重试上限及补偿入口。组内大量成员同步可异步执行，但同一成员的一批待办必须原子生成，并展示同步进度及失败状态。 | 审查事务调用链是否包含外部能力；模拟提交前回滚与提交后投递失败，前者不应触发外部副作用，后者应能补投且不丢失事件。 |
| BE-08 幂等与并发 | 每个写接口声明幂等策略。通知确认、发布和任务提交等操作支持幂等键，按用户、操作及键保存请求摘要与结果；同键不同内容返回冲突。存储层设置唯一约束，例如“组通知任务+成员”“任务+提醒节点+时间版本”“文件+索引版本+切片序号”；个人手动创建不按标题去重。编辑使用版本号条件更新，冲突返回 409。幂等键有效期必须覆盖约定的重试窗口；过期后仍由业务唯一约束防止重复副作用。 | 顺序及并发重复提交，结果只产生一次；同键异内容被拒绝；两个会话修改同版本时后一次返回冲突，先前结果保留。 |
| BE-09 分页、排序与筛选 | 列表统一使用 `page`、`page_size`、`sort`，默认页码 1、每页 20，最大每页 100；超出上限截断为 100并在响应中返回实际分页值，非正数和类型错误直接拒绝。排序字段、方向、筛选字段和枚举值均使用白名单；值采用参数绑定，不拼接查询。资料、待办及小组列表先应用权限范围，再筛选和分页；总数也不得包含无权访问的数据。 | 测试默认值、超限值、非法方向与注入字符串；检查返回分页值、结果集及总数是否一致且仅含授权数据。 |
| BE-10 排序的唯一兜底键 | 排序字段不唯一时追加唯一键，如 `deadline_at ASC, id ASC`，并声明空时间的排序位置。列表与日历使用一致时间语义。偏移分页不承诺并发增删时的快照一致性；如业务要求稳定连续遍历，须使用含全部排序键的游标或快照，并定义游标失效规则。 | 构造相同截止时间、相同创建时间及空时间记录，在数据不变时翻页不得重复或遗漏；要求稳定遍历的接口另测试并发增删场景。 |
| BE-11 非法筛选的失败策略 | 字段不存在、类型不符、枚举越界或日期区间非法时返回明确参数错误，禁止静默忽略并退化为无筛选查询。请求指定无权访问的小组时返回约定的权限错误，不得退回个人或全部范围。权限条件由服务端身份和成员关系生成，不能由客户端传入的用户标识替代。 | 提交未知字段、越界状态、逆序日期及其他小组标识，均应失败，不得返回更大范围的数据。 |
| BE-12 配置外置 | 部署地址、数据库连接、密钥、模型配置、依赖超时和特性开关从环境变量读取，不写死在代码中，也不提交真实 `.env`。提供仅含占位值的 `.env.example` 和必填项说明；按已启用功能校验配置，缺失或格式错误即启动失败。关闭的可选能力可不配置，但对应接口必须明确返回不可用。纯业务常量可集中定义；密钥不得写入错误响应或日志。 | 删除启用能力的必填环境变量或填入非法值，启动应失败并提示配置项名称；检查仓库、日志与响应不存在真实密钥。 |
| BE-13 文件处理与异步任务 | 上传、类型检查、OCR、解析、切片、向量化及日报生成采用可查询的后台任务；记录任务类型、所属用户/小组、状态、进度、尝试次数和错误摘要。文件大小、页数、字符数及像素限制遵循产品规范，同时核对扩展名、内容类型和实际文件内容；原文件使用服务端生成的存储标识。任务设置超时、有限重试和退避，永久失败进入人工重试或补偿入口；重复执行不能重复生成任务、切片或索引。上传成功但业务记录失败的孤立文件须定期清理。 | 模拟伪装格式、超限文件、任务中断、重复消费与重试耗尽；检查失败可见、重试可控、无重复记录及孤立文件可清理。 |
| BE-14 数据权限与 AI 检索 | 身份由可信认证上下文确定，文件、待办、小组和任务均校验对象级权限。向量检索前限制授权范围，返回结果后再次校验原文件当前权限及有效版本；缓存按用户或授权范围隔离，权限撤销和删除必须使旧缓存失效。回答引用仅由实际检索到且当前有权访问的片段生成；文件内容不能作为系统指令执行。模型输出视为不可信输入，经结构校验后保存草稿，不可直接写正式待办。 | 使用组外账号、退出成员、失效缓存和带指令的文件测试；不得泄露文件、切片、历史引用或跨用户答案，异常模型输出不得写入正式业务数据。 |
| BE-15 时间与提醒一致性 | 精确时刻以 UTC 存储并携带用户时区语义，仅日期使用独立日期字段及精度标记，禁止用虚构时刻替代未知时间。提醒按产品规则计算，由后台调度；消息生成与去重记录在同一事务完成。改期、完成、撤回及提醒处理使用版本或锁协调，投递前复核状态与时间版本；失败重试不得重复生成站内消息。 | 测试跨时区、日期边界、重复调度、并发完成与改期；旧节点失效，未到期任务不误判逾期，站内消息不重复。 |
| BE-16 日志、审计与验证 | 请求、Outbox、后台任务及外部调用通过请求标识和任务标识关联；日志记录耗时、状态及脱敏错误，不记录密码、令牌、完整文件正文或完整模型提示。关键业务审计记录操作者、对象、动作、版本与时间，限制修改和访问权限。为权限隔离、状态流转、原子提交、幂等、并发冲突和任务重试建立有意义的自动化测试；外部能力通过适配层替身模拟失败。 | 根据一次上传或发布追踪全链路；抽查敏感信息及审计权限；验证核心规则在依赖失败、重复执行和并发情况下仍成立。 |
