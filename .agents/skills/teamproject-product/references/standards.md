# 产品设计规范

本项目以个人日常使用为主，覆盖学习、工作与生活中的通知、待办和资料。首期覆盖个人流程、小组创建与加入、组内资料共享及通知发布。成员按组选择是否接收同步待办。桌宠、动态壁纸、日常事件记录等在纳入迭代时再定义场景、权限和验收。

本文约束后续产品设计与实现。每项能力在开发前都应明确页面入口、适用角色、状态与验收方式。README 已存在，开展页面设计时应补齐下表要求的章节。

| 规范项 | 本项目的设计要求 | 检查与验收方式 |
| :--- | :--- | :--- |
| PROD-01 用户与场景 | 在 README 的「用户与场景」中维护“角色—触发操作—能力—承载页面”的对应关系。首期以个人用户为主，覆盖注册登录、上传通知并确认待办、查看待办、阅览与轻编辑个人资料、问答、查看日报及提醒。首期还覆盖小组成员和管理员的创建、加入、共享与管理场景，以及成员按组设置通知同步。每条能力必须落到具体页面或页面内明确的操作上。 | 逐项对照需求与页面，检查是否存在没有入口的能力、没有明确服务对象的页面，或无法完成的操作路径。 |
| PROD-02 页面清单与信息架构 | 在 README 的「页面清单」维护路由及层级。首期为注册/登录、首页、通知导入与解析确认、待办列表与详情、资料库与文件详情、AI 问答、提醒提供明确入口。待办按时间展示，含来源、标题、详情、开始及截止时间。采用日历时复用同一待办模块。日报常驻首页。首期提供小组列表与详情、组资料与组通知入口。在小组内提供「同步组通知到我的待办」开关，明确作用范围和生效时机。每项功能只有一个规范路由，可有多个快捷入口，但必须指向同一流程并保留来源上下文。未知路由显示 404；未登录访问受保护页面跳转登录，成功后返回原页面；无权访问的对象不泄露内容。 | 按路由清单逐个访问，检查导航、返回路径和深链接；测试未知地址、未登录地址及其他用户的对象地址。孤立页面、同功能的重复实现或越权展示均为缺陷。 |
| PROD-03 视图状态完备性 | 每个数据视图都须定义加载中、正常、错误、空状态及对应操作；异步处理展示处理中、失败和可重试状态。文案模板：“正在加载{对象}…”；“暂无{对象}，可{下一步}”；“{对象}加载失败，可能是{原因}，请{操作}”。例如“暂无待办，可上传通知并确认任务”。上传处理、资料索引、AI 回答和日报生成不得无限转圈；超时后提示状态、恢复方式及后台任务是否继续。 | 使用无数据账号、模拟服务失败、处理中和超时场景逐页检查；空白无提示、错误后不能恢复或无限加载均为缺陷。 |
| PROD-04 文案与术语 | 在 README 的「术语表」统一使用“通知、资料、待办、开始时间、截止时间、小组、待确认、每日报告、提醒”。“截止时间”不混写为 DDL、结束时间等；“未完成/已完成”为完成状态，“临期/逾期”为时间标签。错误提示包含发生了什么、可能原因、可执行下一步；原因未知时明确说明，不能编造。AI 建议与已确认事实在文案上明确区分。 | 检索页面、接口说明及文档中的同义混用；抽查上传失败、解析失败、无权限和 AI 不可用提示是否给出下一步动作。 |
| PROD-05 表单与校验 | 标明必填项，失焦时校验字段格式，提交时全量校验；错误就近显示，并保留已填写内容。上传入口明确区分通知和资料，默认为个人私有。上传到小组时，用户须明确选择目标小组并看到共享范围。任务标题必填；时间可留空，已填起止时间须顺序合理。提交中显示进度并抑制重复点击；后端重新校验字段、权限并保证幂等，不能仅依靠按钮禁用去重。 | 逐表单测试空值、非法格式、逆序时间、失败重试和连续提交；同一确认或发布操作只产生一份结果，失败后无需重新填写全部内容。 |
| PROD-06 视觉基线 | 统一设计令牌：间距采用 4/8/12/16/24/32，字号采用 12（辅助）、14（正文）、16（小标题）、20/24（标题）。成功、警告、错误、处理中使用统一语义色，并配文字或图标。页面复用已有组件及令牌，按启用的视图补充所需组件。 | 检查新增页面是否复用组件、字号和间距令牌；检查待办、处理状态及错误反馈的语义是否一致，不能只凭颜色区分。 |
| PROD-07 可达性与响应式 | 主流程支持键盘操作且焦点清晰；弹窗打开后管理焦点，关闭后返回触发处；控件关联标签，错误可被辅助技术识别。普通文字对比度至少 4.5:1，大号文字至少 3:1。断点矩阵：小于 768px 为单栏、折叠菜单，确认页原文/结果上下排列；768–1199px 使用紧凑导航，宽表格在容器内滚动；1200px 及以上使用侧栏，确认页可并排预览。采用日历时，移动端提供列表切换。 | 仅用键盘走通登录、上传、确认和完成待办；在 375、768、1024、1440px 宽度核验，页面不得整体横向溢出，关键操作与信息不得被遮挡。 |
| PROD-08 状态与流程 | 各流程必须记录状态枚举、流转条件及允许操作。文件处理：排队→处理中→成功/失败，失败可重试；个人通知由待确认进入已确认。组通知由有权成员确认后发布，发布后可撤回。资料索引状态独立展示。待办：未完成→已完成，恢复须有明确入口并留痕。前端提交“确认、发布、撤回、完成、恢复”等动作，由后端校验权限与当前状态并决定流转，不能接受任意目标状态。已确认或发布的内容通过显式修订入口保存新版本；已撤回内容不可原地恢复发布。并发操作采用版本校验，后操作方收到“该记录已被处理或更新，请刷新后重试”，不能静默覆盖。 | 对非法流转、终结状态修改和过期版本提交发起请求，应被拒绝；两个会话同时确认或修改同一通知，仅有效操作成功，已有结果和历史不被覆盖。 |
| PROD-09 导入与导出 | 首期支持粘贴文本、PNG/JPG、PDF、DOCX；每次提交一个文件，单文件不超过 20MB，PDF 不超过 200 页，DOCX 提取正文及粘贴文本不超过 10 万字符，图片不超过 2000 万像素。限制在入口展示并由后端校验，超限或损坏整份拒绝。通知先解析预览，确认后以整批事务生成待办；任一任务校验失败则全部不生效，按任务序号、页码或段落给出原因。资料上传后可查看提取结果和处理状态。个人资料默认私有，发布到小组前明确确认共享范围。资料可阅览原文件或提取内容，轻编辑限于标题和可编辑文本，原附件单独保留。保存时显示当前内容版本的索引状态，索引完成后才可用于问答。首期无批量表格导入和导出入口；后续增加时须声明行数上限、提供模板，按行报告错误并整批生效；导出须限定权限与范围、脱敏敏感字段并留痕，大批量走异步。 | 上传超限、损坏、不支持格式及 OCR 无有效文字的文件，检查是否明确拒绝；在候选任务中混入非法项，不得生成半批待办。验证可预览资料、保存编辑且编辑失败可恢复输入，问答只使用当前已完成索引的内容。新增表格导入时检查行号和模板；新增导出时检查越权范围、脱敏与记录。 |
| PROD-10 AI 解析与人工确认 | 抽取任务标题、详情、开始时间、截止时间及来源片段，一份通知可对应多个任务。确认页允许对照原文编辑、补充、删除或新增候选任务；未经确认不得生成正式待办或向小组发布。缺失时间保持为空，模糊、矛盾或推断信息标记待确认；相对日期展示采用的原文日期基准，不能静默以上传日期替代。任务拆解先给建议，确认后才保存。 | 使用无时间、相对日期、多事项、时间冲突和低质量截图测试；检查不确定字段提示、原文定位及编辑能力；未确认时不得出现正式待办。 |
| PROD-11 小组共享与权限 | 个人内容默认私有。用户可以创建或加入小组，每位当前成员均可上传和阅览组资料。编辑权限显式区分上传者、管理员和普通成员。管理员可管理成员与组内容。成员可确认发布自己上传的组通知。组内通知的可见性按成员权限判定。权限同时约束页面、接口、原文件、预览、切片检索和引用；缓存或历史回答中的来源也须重新校验访问权。同步设置按账号和小组独立保存，默认关闭。开启后仅同步该组新发布的通知。关闭即停止后续同步和仍未写入的同步任务，已生成的待办保留。组通知按“通知任务标识+用户”去重，待办标明小组来源，成员完成状态、个人备注与提醒独立。修订更新已同步待办的共享字段并提示变更，保留个人状态。撤回后保留来源标记并停止提醒。退出后保留个人待办快照，并撤销该成员的组文件及检索权限。 | 使用两个小组、两名成员和一名组外用户验收。验证同组成员可各自开关，同一成员可对不同组分别设置。检查默认关闭、开启后新通知入待办、关闭后通知仍可在组内查看且已同步待办保留。另查重复投递、修订、撤回和退出，核对个人状态、提醒与共享权限。 |
| PROD-12 AI 问答与来源追溯 | 提问默认使用个人范围。可显式选择指定小组或全部可访问内容。个人资料与纳入知识库的通知均可检索，长内容按语义切片并向量化，保留文件版本、来源位置和归属信息。查询任务时间、完成状态时优先使用已确认待办；资料回答引用可打开的来源位置。无依据时说明未找到，来源冲突时展示差异，不得编造截止时间、引用或资料内容。文件内指令只视为资料内容，不能改变系统规则和访问权限；AI 建议不得自动修改待办。文件删除或权限撤销后立即排除检索，异步清理索引期间也不得返回内容。 | 提问已知事实、无答案问题及冲突材料，验证他人资料不可检索。验证未授权小组的资料不可检索。核对引用是否支持结论及位置是否可访问。删除文件或撤销权限后再次提问，不得命中失效内容。 |
| PROD-13 时间、日报与提醒 | 按用户时区显示，默认 Asia/Shanghai；区分“仅日期”“精确时刻”“未知”，仅日期不随时区换算改变。仅日期任务从当地次日 00:00 起判为逾期。首页常驻日报，包含今日任务、未来 7 天截止事项、逾期任务及建议，显示更新时间并支持刷新。组内新增资料仅展示用户当前有权访问的内容，与组通知同步设置独立。基础清单按当前业务数据生成，AI 建议不可用时仍可查看清单。首期采用站内提醒：精确时刻默认提前 24 小时和 1 小时，仅日期默认前一天与当天 09:00，允许调整或关闭。错过节点不补发；无截止时间、已完成、来源已撤回的任务不发送截止提醒。提醒按任务、节点及时间版本去重；改期后使旧节点失效并重算，发送前再次校验任务状态。 | 对比首页、列表、日历、问答和提醒中的同一任务；测试日期边界、时区变化、无时间、完成、改期及撤回。重复执行提醒任务不得重复发消息，旧时间节点不得继续提醒。 |
| PROD-14 变更可追溯 | 产品形态、权限、路由、术语、流程或导入限制变化时，同步更新本文与 README 的相关内容，在变更记录说明改动、原因和影响范围。通知修订、撤回、待办恢复、权限调整等关键操作记录操作者、时间和变更摘要，供有权用户查看。 | 对照变更说明、README、页面与实际行为；未同步差异即为缺陷。抽查业务历史，应能说明谁在何时做了什么，且历史不能被普通编辑覆盖。 |

后续新增能力沿用上述规范；未定义的状态、权限或失败处理应先补充设计再实现。
