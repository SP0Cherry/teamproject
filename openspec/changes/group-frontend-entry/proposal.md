## Why

后端的小组能力已经相对完整（创建、凭邀请加入、退出、成员管理、按组同步、组通知发布、组资料隔离授权均已实现），但前端 `Groups.vue` 只暴露了创建、凭令牌加入和名称列表三项，导致成员管理、同步开关、组通知发布、组资料共享等能力用户根本无法触达。同时成员列表接口只返回裸 `user_id`，前端即使想展示成员也无法识别身份。近期课程交付要求小组功能真正可用，需要优先把已有后端能力接到前端，并用最小的后端契约补全让成员界面可用。

## What Changes

- 新增组详情页（路由 `/groups/:id`），集中承载组信息、成员、同步、组通知、组资料五个操作区，列表卡片可点击进入。
- 组列表页增强：卡片展示组描述、成员数、本人角色和同步状态，并提供退出组入口（owner 置灰提示需先转让所有权）。
- 组详情页接线已存在的后端接口：展示/复制邀请令牌、管理员重置令牌、退出组、成员列表与移除成员、「同步组通知到我的待办」开关、组通知发布与列表与撤回、组资料上传与列表与删除。
- 后端契约补全（非管理能力，为成员 UI 的必要前置）：`GET /groups/{group_id}/members` 关联 `users` 表，返回 `username` 与 `joined_at`，使成员列表可识别身份。
- 明确不在本变更范围：转让所有权、解散组、编辑组信息（名称/描述）、成员角色升降、组通知修订、邀请令牌过期机制——留待后续批次。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `group-collaboration`: 细化并新增可观察要求——组内提供管理界面与操作入口，成员列表展示可识别的成员信息（用户名、角色、加入时间），成员可在组内操作同步开关、查看与发布/撤回组通知、上传与管理组资料，且这些入口受成员角色与授权约束。

## Impact

- 前端：`frontend/src/router/index.ts` 新增组详情路由；新增组详情视图与列表页改造；新增/复用 API 封装（groups、notifications、attachments）。
- 后端：`backend/app/repositories/group.py` 的 `list_members` 关联 `users` 表；`backend/app/api/v1/groups.py` 成员列表序列化增加 `username`、`joined_at` 字段（非破坏性，仅新增字段）。
- 文档：README 页面清单与用户场景同步补齐组详情页入口（PROD-02、PROD-14）。
- 测试：后端成员列表契约测试（返回字段与非成员拒绝）；前端组详情页关键路径的组件/路由验证。
- 不影响：数据库结构无迁移（仅查询 join，不新增列）；现有接口无破坏性变更。
