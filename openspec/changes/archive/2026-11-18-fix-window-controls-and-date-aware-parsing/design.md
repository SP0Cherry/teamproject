## Context

动机见 [proposal.md](proposal.md)。以下为本次只读检查所见，均不等同于运行复现：

- 项目为 FastAPI + Vue 网页，`frontend/package.json` 没有桌面窗口框架，`WorkspaceLayout.vue` 只有侧边栏和 API 设置按钮。用户确认问题 1 是浏览器原生最小化按钮；用户补充浏览器为 Edge，其他页面正常而本程序相关页面均有最小化问题；版本及真实窗口行为仍待现场复现。
- `todo_parser.py` 单轮调用 `chat_completion`；提示词使用固定 2024 年日期示例，另一示例把“下周三”的日期置空。`_extract_date` 取 UTC 今日，并以 `delta <= 0` 将本周已过日期顺延；`_combine_datetime` 默认 09:00 并直接赋 UTC。
- `notification_parser.py` 未注入日期基准，`_normalize_deadline` 将无偏移时间当 UTC，非法时间返回空；两条解析路径时间契约不同。
- `model.py` 只读最终 content，没有工具消息循环；日志还包含 `user_input` 和 `raw_response`，本次提示词时间上下文接入必须同时移除这些正文日志。
- `TodoAdd.vue`、`Schedule.vue` 使用 UTC 分量作为显示值。Todo 只有 `due_at`；`HomeService` 按 UTC 今日分类。数据字典把仅日期写成 00:00 UTC，与 DATA-01、PROD-13 和主规约冲突；本变更以独立日期修正实现和字典，不削弱规范。
- `audit-and-fix-prototype-bugs` 仍是活动变更且任务已勾选；其中侧边栏和解析召回率内容不作为本问题根因或验收证据。本变更扩展后的时间规约优先于其旧的默认时间做法，实施时避免两个变更同时修改 parser。

## Goals / Non-Goals

**Goals:** 建立可注入时钟、模型仅抽取语义且代码计算日期的解析链；保持文本/文件/通知的时间字段完整；支持确认后往返一致；独立诊断宿主窗口。

**Non-Goals:** 不引入 MCP 工具/SDK、agent 循环、外部时间服务、桌面外壳或任意工具执行；不实现新的月历功能或重建提醒系统，不借此完成历史全量合规审计；不自动修改浏览器配置、重启用户浏览器、关闭窗口或发布部署。

## Decisions

### 1. 浏览器最小化采用环境诊断，验收独立记录

先记录浏览器名称/版本、Windows 版本、普通/最大化/全屏状态及是否实际为 PWA/嵌入式宿主。分别在项目页、空白页、另一个普通站点测试同一窗口的原生最小化，并对照键盘窗口最小化及另一浏览器。判据是窗口离开桌面并能从任务栏恢复原页面和表单，而不是按钮动画。最大化窗口的快捷键可能先恢复普通尺寸，再最小化，须区分两次状态变化。

若空白页同样复现，记录为宿主故障及后续处置，不修改 Vue 侧边栏。若仅项目页复现，采集最小复现、页面全屏状态及浏览器诊断，再实施有证据支撑的页面修复；不能预先断言浏览器缺陷或虚构网页原生窗口控制 API。诊断不以“另一个浏览器能用”代替原问题已修复。需要宿主升级或配置变更时提交具体操作及影响，保留现场；不将缺少宿主源码记为项目已修复。

参考：[Microsoft 窗口快捷键](https://support.microsoft.com/en-us/accessibility/windows/keyboard-shortcuts-in-windows?WT.mc_id=EM-MVP-4025011)。此项无项目 capability 增删，因此不制造 workspace-ui delta。

### 2. 在发送前向解析提示词注入可信时间上下文

保留现有单轮模型调用链，在待办文本/文件解析和通知解析共同使用的提示词装配处增加服务端时间上下文。每次真正发送模型请求前（文件提取及排队之后）从可注入业务时钟读取一次 UTC 时刻，再以服务端业务时区派生全部字段：

| 模板变量 | 示例与语义 |
| --- | --- |
| request_sent_at | 2026-11-08T10:00:00+08:00，含偏移的发送时刻，精确到秒 |
| current_date | 2026-11-08，业务时区中的当前日期 |
| current_time | 10:00:00，业务时区中的当前时间 |
| current_weekday | 7，周一=1、周日=7；提示词同时显示中文星期日 |
| timezone | Asia/Shanghai，IANA 时区 |

这些值每次解析都注入，不以检测到相对日期为条件，不从模型知识、浏览器日期、用户传参或固定示例推测。当前没有用户时区偏好时复用 settings.timezone，默认 Asia/Shanghai；非法时区启动失败。时钟读取或上下文校验失败时终止该次模型发送并返回可恢复错误，不能拿上次请求时间兜底。

版本化系统提示词声明上述允许填充的变量，在“可信请求时间上下文”段落填入服务端生成值；正文以明确边界放在用户数据消息中，任何正文都不能拼入系统规则。模型获得真实发送日期和时间后抽取日期表达，由日期业务服务计算和复核日历日期。当前时间不是默认截止时间，不能用于填补缺失的日期或时刻。

一次发送使用一个快照，同时交给提示词装配、相对日期换算、结果校验和 date_basis。后续新请求、用户重试以及实际网络重试都在发送前重新读取；若重试跨午夜，前次失败尝试的结果丢弃，仅采用成功响应所属尝试的快照。模型响应跨午夜返回时，不改用响应到达时间重算。无需轮询时钟或保持后台日期缓存。

集中配置保留总耗时 60 秒、单次模型最多 30 秒且不超过剩余预算、可恢复网络错误最多重试 1 次；失败重试与退避均计入总预算。不新增工具轮次、工具超时或 MCP 并发配置。日志记录 request_id、能力、模型和提示词版本、耗时、用量（缺失标未知）、尝试次数及结果，移除原有 user_input/raw_response 正文日志，不记录完整装配后的提示词、回答或 API key。

本次不引入 MCP SDK、日期工具、MCP server/client、子进程、外部时间服务或 agent 工具调用循环。使用现有 Python 日期时区能力和模型适配层；删除旧方案的依赖安装和工具支持前置条件。既有每请求模型配置及部署出站白名单边界保持适用。

替代方案：进程启动时固定注入日期会过期；仅注入日期不能完整表达用户要求的发送时刻与时区；MCP/agent 工具方案已由用户明确取消。选择每次发送前填充可信模板变量，能复用现有单轮接口。

### 3. 模型提取表达，日期服务计算具体日期

为两个 parser 统一增加结构化时间语义：绝对日期、当地时间、相对类型（today/tomorrow/this_week/next_week）、星期、原文时间片段、原文显式基准。模型只做语义抽取；服务端核对来源片段确实在输入中，校验年月日/小时分钟和精度，再由日期服务换算。本周目标日 = 基准日所在周的周一 + weekday - 1，下周再加 7 天；本周已过不顺延。中文和英文规则解析共用该计算器。

基准优先级：原文明确且可核查的发布日期/时间基准 > 本次模型请求发送时的当前日期。多条互相冲突的原文日期不擅自选一条，保留空日期和待确认原因。无明确基准时以发送日给建议，展示 `date_basis`（日期、时区、source=source_text/request_time、来源片段）与 `needs_confirmation`；不得把请求发送日期标为通知发布日期。用户可修改候选日期或基准；修改基准后所有依赖它的候选重算，明确手改日期的候选保留用户值。

提示词版本化（分别定义 todo/notification 新版本），删除无基准历史日期示例；系统只含可信规则和声明的可信时间上下文变量，正文以边界标记放用户数据消息。日期换算由代码兜底复核，拒绝模型多余的身份、权限及状态字段。

失败策略：待办解析保留规则降级，但返回 parser=rule、degraded_reason，不把降级声称为 LLM 成功；共享同一可验证基准，若无法取得可靠发送时间上下文且原文也无基准则相对日期留空。通知解析返回现有 DEPENDENCY_UNAVAILABLE/DEPENDENCY_TIMEOUT（503/504）或 BUSINESS_RULE（422，非法输出）并保留输入供重试。合法绝对日期可以独立解析，不依赖当前日期基准。用户主动选择演示模式时规则解析使用同一个业务时钟并清楚标为规则来源。

### 4. 时间契约和兼容迁移

两条路径统一到以下时间值，通知旧 `deadline` 字段作为 `due_at` 的兼容映射，而非第二套换算规则：

| 字段 | 含义与不变量 |
| --- | --- |
| due_at | 带时区 UTC 精确时刻，仅 datetime 精度可非空 |
| due_date | 独立 DATE/ISO 日期，仅 date 精度可非空 |
| due_precision | datetime/date/unknown，与上述字段互斥约束一致 |
| due_timezone | 用于解释和显示时刻/判断日期边界的 IANA 时区 |
| date/time | 候选表单局部值；缺失部分为空。仅有 time 时作为待补日期的候选元数据保留，不制造 due_at |

解析 API 增加精度、基准、警告及降级字段；通知 parsed JSON 同样保存这些元数据，读取不丢失。候选仅有时间、没有日期时，确认前提示补日期或明确接受无截止时间，时间信息保留在说明中；不虚构当天日期。候选时间和 UTC 冲突时拒绝，不能接受两种不同真值。确认及批量创建在全部字段验证后才写入，错误关联任务序号和字段，整批不生效。

增量迁移为 Todo 加 due_date、due_precision、due_timezone 与一致性约束；旧 due_at 非空标记 datetime，空值标 unknown，保留原数值，历史展示时区按部署业务时区补齐，不从 00:00/09:00 猜测精度。旧客户端只有合法带偏移 due_at 时推导 datetime；只有新字段的日期记录由新客户端正确显示。旧客户端遇仅日期数据只能视为无精确时刻，需在 README 声明其展示限制。无偏移旧请求不能再暗中当 UTC，应返回字段错误并提示带时区或采用新字段。更新数据字典，移除“仅日期存 00:00 UTC”的错误说明。

前端提取公共时间函数，使用业务 IANA 时区格式化/分组，并在时区上下文中将当地表单值交由后端转换；不拼接 Z 冒充 UTC、不依赖浏览器宿主时区。非法 Date 显式判错。TodoAdd、NotificationConfirm、Schedule、Todos、Home 和后端首页分类统一语义。仅日期的逾期规则为业务当地次日零点。提醒本轮只回归已有精确时刻行为并验证未给未知时间制造提醒，不新增自动提醒调度能力。

替代方案：继续只用 due_at 会丢失日期精度，无法区分未知时刻；批量修正旧值无法知道过去输入的真实时区，可能破坏正确历史数据。

## Risks / Trade-offs

- [时间上下文过期或字段混用] → 每次实际模型发送前统一取快照；排队/提取后刷新，重试绑定其对应响应，固定时钟覆盖午夜边界。
- [跨模块触及文件较多] → 实施前按“兼容迁移和时间契约”“发送时刻提示词注入”“前端时间接入”拆成独立可验收的关联变更/PR，单条变更手工文件原则上不超 15，不能只拆 commit 绕过总文件数；确实无法拆开的原子超限须按 REV-06 登记并获维护者确认，不能在此预先宣称豁免。当前提案作为三个问题的总追踪入口。
- [旧客户端无法显示仅日期] → 保留 due_at 语义，文档声明限制，先扩结构后上新客户端；不要为兼容伪造时刻。
- [日期基准误判] → 标明发送时间推算建议和原文基准，冲突待确认；以固定时钟和合成通知回归。
- [注入时间后仍有模型误判] → 日期运算在代码中执行，替身验证实际发送消息及语义校验，真实模型单独评测；不把提供当前时间等同于解析正确。
- [原生按钮故障无法在仓库修复] → 单独记录复现环境及未完成状态，日期修复通过也不能宣称三个问题全部解决。

## Migration Plan

1. 在独立测试库验证增量迁移、约束、旧记录数值不变、重复升级及恢复。先扩结构并保持旧代码可读取，不删除旧字段；部署迁移与应用升级分阶段，不在本轮执行发布。
2. 上线新解析/读取契约，再更新前端，回归确认前零业务写入、合法确认后日期往返、首页/日程一致。配置统一限值，每次发送前装配时间上下文；时间上下文或模型故障仅影响解析能力，不触发整个 API 服务反复重启。
3. 应用可回退上一版本并保留新增列；回退后的旧版不能完整展示仅日期记录，暂时禁用新增解析写入并明确限制。数据库不直接 downgrade 丢弃日期值；若必须回退结构，先导出新增精度字段备份并采用审核过的数据恢复方案。
4. `docs/changes/fix-window-controls-and-date-aware-parsing/record.md` 分别归档变更、验证、评审；浏览器诊断另留一节，真实模型评测单独报告并关联。实现与环境问题分别判定完成状态，不自动部署。
