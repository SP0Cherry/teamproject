## ADDED Requirements

### Requirement: 待办解析召回

系统 SHALL 支持用户通过文本或文件输入解析待办候选，解析结果须覆盖输入中全部可识别的独立事项。对包含多个事项、嵌套时间地点或长文本的输入，每个可识别事项 SHALL 生成一条候选，缺失字段以 null 表示而非丢弃整个事项。解析须标注来源（LLM 或规则），LLM 输出畸形或超时 SHALL 回退规则解析，规则解析结果同样逐项校验。

#### Scenario: 多事项文本不丢项

- **WHEN** 用户输入包含三个以上独立事项的文本（如"明天上午十点开会，下午三点交报告，晚上八点和朋友吃饭"）
- **THEN** 解析结果返回至少三条候选，每条含标题及可识别的日期时间，解析来源为 LLM 或规则

#### Scenario: 字段缺失不丢弃事项

- **WHEN** 输入事项缺少时间或地点
- **THEN** 对应字段为 null，该事项仍作为候选返回，不被过滤

#### Scenario: LLM 失败回退规则

- **WHEN** LLM 返回非 JSON 或超时
- **THEN** 系统使用规则解析并在响应中标记 parser 为 rule，不返回 500 错误
