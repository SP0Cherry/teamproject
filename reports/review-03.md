# 审核记录 03：人工确认（机器给不出判据的项）

机器只能产出信号，以下三项的最终判定需人工确认；确认结论已写成规则或落到指定位置。

---

## 项 1：依赖扫描例外的适用性判定

### 手段
人工复核 `pip-audit` 报出的 2 条无修复版本漏洞，结合代码配置判定是否可被本应用利用。

### 查了什么
- `PYSEC-2026-4298`（python-jose 3.5.0，无修复）：描述为「未显式限制算法时，攻击者持公钥可伪造 HS256 令牌」。
- `PYSEC-2026-1325`（ecdsa 0.19.2，无修复，python-jose 传递引入）：描述为「P-256 侧信道时序攻击，影响 ECDSA 签名/密钥生成；ECDSA 验签不受影响；上游无修复计划」。
- 应用实际用法：`backend/app/core/security.py` 第 41/46/62 行均显式 `algorithm="HS256"` / `algorithms=["HS256"]`，使用对称密钥，不使用 ECDSA 签名。

### 判据
漏洞的利用前提在本应用是否成立。

### 结果（人工确认结论）
- PYSEC-2026-4298：利用前提是「未显式限制算法」，本应用显式限制为 HS256 且用对称密钥，**不可利用**。
- PYSEC-2026-1325：仅影响 ECDSA 签名/密钥生成，本应用只用 HS256，不调用 `ecdsa.SigningKey`，**不可利用**。
- 结论落点：两条均在 `Makefile` 的 `PIP_AUDIT_IGNORE` 登记，并在 `reports/checklist.md` 第 6 类与本文件记录理由（REV-06 例外要素：范围=依赖门禁、理由=无修复版本且评估不可利用、风险=若后续改用非对称签名需重评、替代控制=显式算法白名单 HS256、责任人=提交者、批准人=课程评审、到期日=长期/下次改签名算法时重评）。

### 复跑命令
```bash
make check-security   # 应输出 "No known vulnerabilities found, 2 ignored"
```

## 项 2：演示视频内容是否满足要求

### 判据
课程第 ⑤ 节对演示视频的要求。

### 结果
待人工录制后确认。结论落点：`report.md` 头部「演示视频地址」字段，以及本变更任务 5.4。

## 项 3：GitHub main 分支保护是否生效

### 手段
人工在 GitHub 仓库设置中开启 `main` 分支保护，要求 CI status check 通过方可合入，并截图留证。

### 查了什么
`Settings → Branches → Branch protection rules` 是否对 `main` 启用「Require status checks to pass before merging」并选中 CI 检查。

### 判据
未通过 CI 的提交不可合入 `main`。

### 结果
待人工开启后确认。结论落点：保护设置截图补入 `reports/`，并在 `README.md` 门禁说明中登记；对应本变更任务 5.5。

### 复跑命令
人工在 GitHub UI 核对；可尝试推送一个故意失败的提交验证无法合入。
