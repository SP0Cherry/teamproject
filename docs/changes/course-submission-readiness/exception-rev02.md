# 例外登记：REV-02 变更规模上限（手工文件 > 15）

本变更手工维护文件共 22 个，超过 REV-02 的 15 个上限，按例外流程登记（REV-06）。

- **范围**：`course-submission-readiness` 变更全部手工维护文件（门禁与 CI 5 个 + 并发幂等硬化 5 个 + 依赖修复 1 个 + 课程证据 8 个 + 交付文档 3 个 = 22 个）。锁文件、生成文件、`backend/.coverage` 等不计入。
- **理由**：这是一次原子的课程交付变更。已批准规约把「门禁基础设施」「并发幂等满足只产生一份结果」「课程证据 reports/」「根 report.md」放在同一交付契约内；门禁必须先红后绿才能作为课程证据（`reports/review-02.md`），并发硬化是 apply 阶段为满足规约而产生、且其红→绿证据是报告的核心论据，拆开提交会断裂证据链，也无法单独验收「门禁全绿」这一交付条件。变更内不含无关重构或格式化。
- **风险**：单次评审面较大，易遗漏。已通过以下替代控制缓解（见下）。
- **替代控制**：
  1. 门禁可重放：`make check` / `make check-security` / `make bench` 覆盖回归，升级依赖后全量回归仍绿。
  2. 证据交叉链接：`docs/changes/course-submission-readiness/` 三份材料与 `reports/` 互链，每个结论可追溯到真实命令与退出码。
  3. 并发硬化附变异验证（去唯一索引复红），证明用例能捕获回归。
  4. 评审结论 `review.md` 逐项核对完成定义，遗留项明确标注为人工动作而非机器通过。
